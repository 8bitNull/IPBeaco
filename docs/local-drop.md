# 本地 DROP 网段

`drop-local` 显式读取配置中的 Spamhaus IPv4/IPv6 DROP 官方 JSON 端点，仅生成
本地网段批次。它不授予公共再分发许可；默认配置的两个 DROP 来源仍保持
`enabled = false`、`public_approved = false`。公开八列表、Pages 更新及 `data`
状态分支继续使用原来的准入规则。本命令不处理 ASN，也不调用设备 API。

安装步骤见 [README](../README.md)。在项目目录运行：

```bash
ipbeaco drop-local --config config --state drop-local-state \
  --out drop-local/local-first --build-id local-first
ipbeaco validate-drop-local --dir drop-local/local-first
```

`--config` 是包含 `sources.toml`、`policy.toml`、`allowlist.txt` 的配置目录；
`--state` 是独立的持久本地目录；`--out` 是本次要创建的**完整新目录路径**，
不会自动附加 `--build-id`。后续构建继续使用相同状态目录和新的输出目录。
首次本地状态确实不存在时可直接运行，无需 `--bootstrap`。不要使用公开状态
目录、配置目录或互相包含的状态/输出目录。默认 `drop-local/` 和
`drop-local-state/` 已被 Git 忽略。

每个成功批次只有四个文件：`network-ipv4.txt`、`network-ipv6.txt`、`status.json`
和 `metadata.json`，位于输出目录根部。状态使用 `ipbeaco-drop-local-v1` 协议和
`local_only: true` 标记，每个家族带 `ok`/`empty`、条数、SHA-256、截止时间和
来源标识。它与公开八列表协议不同，公开 `validate --site` 会拒绝本地产物。

CIDR 保留上游边界，不展开、不聚合；过滤非公网地址，强制来源声明的 IP 家族，
数值排序并去重。白名单重叠时排除**整个网段**，`excluded_allowlist` 记录排除项。
TXT 的 `#` 注释及元数据保留上游原始版权、通知、条目归属、原始生成日期、官方
URL 和配置归属信息。即使列表为空也保留这些注释。消费者导入时需支持注释并保留
版权/日期信息；仅本地使用仍需遵守上游 [DROP 使用政策](https://www.spamhaus.org/blocklists/drop-fair-use-policy/)。

## 每日运行与失败处理

安排每天一次运行；**每个来源的两次请求至少相隔 24 小时**。调度延迟后立即补跑
可能尚未满足该间隔，应等冷却结束。请求前先原子保存并同步落盘尝试时间，成功、
HTTP 错误、超时及格式错误都消耗本次额度。一次命令对每个来源最多请求一次，
没有即时重试。任一来源冷却中会在请求前停止整个批次；IPv4 失败时不再请求 IPv6。
状态缺失、校验和不符、格式损坏或尝试时间位于未来都会停止，不可通过删除、回退
状态来跳过冷却。保留并备份整个本地状态目录，排查状态和系统时钟后再运行。

支持 Python 3.12 和具有 `fcntl.flock`、目录同步能力的 POSIX 本地文件系统
（例如 Linux）。Windows 不支持；不支持锁或目录同步的文件系统会报错停止。
所有本地进程必须使用**同一个状态目录**，命令持有非阻塞独占锁，另一个并发运行
会直接失败。不要删除或替换锁文件，也不要让其他程序写入生成目录；每次构建使用
唯一输出路径。这一约定保证所有生产者共享请求额度和提交顺序。

只有 IPv4、IPv6 都成功并通过本地校验，才将同一父目录中的临时批次重命名为
`--out`。不覆盖已有目录，不维护 `current` 链接，不自动导入设备。失败会清理临时
目录，保留已有成功批次和最后接受的异常检查基线，并记录已经发出的请求尝试。
异常检查以最近接受快照的公网目标集为基线，白名单调整不会重置该基线。

每个家族有效期从**上游正文生成时间**加 `policy.snapshot_hours` 计算，最多
48 小时，更短的上游期限优先；抓取时间或构建时间不延长它。超过允许未来偏差
（最多 5 分钟）、生成时间回退、同一生成时间但正文摘要改变、异常增长及格式变化
都会拒绝。相同时间和相同摘要的快照在仍有效时可以再次输出，但保留原有截止时间。
批次生成后再次按完成时刻校验，读取旧批次时也必须重新校验当前时间。

旧 TXT 不会自动失效或删除。运行失败后只能继续使用**仍在有效期内**的上一成功
批次；任一家族到期后 `validate-drop-local` 会拒绝整个批次。消费者应在使用前检查
状态和摘要，到期即停止使用，而不是因下载失败延长旧规则寿命。
